# 项目设计风格总结

## 概览

当前项目的界面风格可以概括为：

- 现代后台工作台风格
- 轻量品牌化，而非强企业表格风
- 以卡片化信息分组为核心
- 偏明亮、柔和、留白充足
- 在标准管理后台基础上加入少量展示型气质

整体不是传统“硬边框、重表格、强密度”的 ERP/中台视觉，而是更接近数据驾驶舱与品牌后台之间的折中方案。

## 视觉基调

项目当前的主视觉关键词：

- 明亮
- 清洁
- 轻盈
- 圆润
- 有呼吸感
- 温和科技感

界面大量使用浅灰背景、白色卡片、低对比边框和大圆角，避免强烈分割线。重点信息通过蓝色主色、高权重标题和局部状态色强调，而不是依赖大面积深色块。

## 色彩系统

全局主题定义集中在 [src/index.css](C:/Users/Haruta/Documents/code/Web/origin_frontend/src/index.css:1)。

### 主色

- `primary`: `#0057C2`
- `primary-container`: `#006EF2`

这套蓝色偏冷静、可信、偏产品化，符合库存管理、分析看板这类后台产品的定位。它承担：

- 主操作强调
- 当前态高亮
- 品牌识别
- 图表主序列色

### 中性色

- `surface`: `#F9F9F9`
- `surface-container`: `#EEEEEE`
- `surface-container-low`: `#F3F3F3`
- `surface-container-high`: `#E8E8E8`
- `surface-container-lowest`: `#FFFFFF`
- `on-surface`: `#1B1B1B`
- `on-surface-variant`: `#414755`

这说明项目采用的是“分层 surface”思路，而不是单一背景色。不同容器之间通过非常轻的明度差来建立层级，整体观感更柔和。

### 状态色

状态色使用直接、明确：

- 蓝色：正常信息、主品牌信息
- 绿色：健康、正向趋势
- 橙色：预警、临期
- 红色：高风险、错误、严重异常

这些状态色通常只在局部出现，例如：

- 标签
- 趋势徽标
- 进度条
- 卡片边框高亮
- 图标底色

整体克制，没有大面积铺色。

## 字体风格

项目使用两套字体：

- 正文：`Inter`
- 标题：`Plus Jakarta Sans`

这是一种比较典型的“信息清晰 + 品牌感补充”组合：

- `Inter` 负责正文、数据、标签、说明文字，保证可读性和通用性
- `Plus Jakarta Sans` 负责页面标题、重点数字、卡片标题，带来更明显的视觉识别

因此当前项目不是纯功能型后台，而是明显追求了一定的品牌化和展示感。

## 形态语言

### 大圆角

项目里大量使用：

- `rounded-xl`
- `rounded-2xl`
- `rounded-3xl`
- 个别超大圆角弹窗

这说明整体形态偏软，不追求锋利、理性、严肃的边界，而是更友好、更现代的产品感。

### 卡片化

卡片是核心设计语言，典型体现在：

- 统计卡片
- 图表容器
- 表格容器
- 详情卡片
- 浮动操作按钮

这些卡片通常具备一致特征：

- 白底或浅灰底
- 轻边框
- 大圆角
- 柔和阴影
- 宽松内边距

### 轻阴影

项目使用了统一的 `ambient-shadow`：

- 不是强投影
- 而是大范围、低透明度、带品牌色倾向的环境阴影

这种处理让界面更“浮”一点，但不会显得厚重。

## 布局风格

### 固定侧栏 + 顶部工具栏

整体采用典型后台结构：

- 左侧固定导航
- 顶部工具栏
- 右侧主内容区

但细节并不传统：

- 侧栏有大圆角右边缘
- 顶栏带半透明和模糊效果
- 主内容区留白较大

这让页面更接近“产品工作台”，而不是传统管理系统。

### 宽松间距

项目常见的容器间距和内边距偏大，例如：

- 页面级 `p-8`
- 卡片级 `p-6` / `p-8`
- 模块之间 `mb-8`
- 栅格 `gap-6` / `gap-8`

因此当前设计是低密度布局，强调浏览节奏和模块分区，不强调一屏塞入大量信息。

## 组件层风格

### 统计卡

统计卡的典型特征：

- 左上图标容器
- 右上趋势徽标
- 下方标题和大数字
- hover 时轻微上浮

这说明设计追求“摘要信息的视觉包装”，而不是只用纯文本罗列数字。

### 图表区

图表容器延续卡片语言，但通常会加入：

- 顶部说明文字
- 模式切换按钮
- skeleton 占位

图表本身色彩保持克制，以蓝色为主序列，辅以浅蓝或红色表达对比关系。

### 表格

表格不是传统强网格表格，而是轻分隔表格：

- 弱化竖向边线
- 表头浅底色
- 行 hover 高亮
- 信息重点通过字重和颜色控制

这符合当前项目整体偏轻的设计方向。

### 弹窗

详情弹窗的风格更具展示性：

- 超大圆角
- 分区明显
- 顶部信息块突出
- 指标、进度、标签混合呈现
- 进入/退出带缩放与透明度动画

这类弹窗已经不只是“表单弹窗”，而是“详情面板”。

## 交互与动效风格

项目使用 `motion` 做了少量动效，特点是：

- 动效数量不多
- 主要服务于反馈和层级变化
- 不追求炫技

目前比较稳定的动效语言包括：

- 卡片 hover 轻微上移
- 浮动按钮 hover 放大
- 图标 hover 旋转或缩放
- 弹窗开合的淡入、缩放、位移

因此整体交互基调是：

- 明确反馈
- 短促自然
- 不打断任务

## 图标与视觉语义

项目混用：

- `lucide-react`
- `@ant-design/icons`

但整体使用方式是统一的：

- 图标尺寸偏小
- 常放在圆角容器中
- 作为信息辅助，而不是主视觉主体

图标更多承担“解释信息块”的作用，而不是形成复杂装饰。

## 当前设计的本质定位

从设计层面看，这个项目更像：

- 品牌化库存管理后台

而不是：

- 标准企业中后台模板
- 高密度专业工业系统
- 完全遵循某个 UI 库默认风格的界面

它的独特性不在复杂视觉，而在于：

- 大圆角
- 柔和分层
- 低密度信息布局
- 轻品牌化蓝色系统
- 卡片化摘要展示

## 后续统一样式时建议保留的设计原则

如果后续要做“统一样式”，建议优先保留以下特征：

- 保留明亮浅色背景 + 白色卡片的整体基调
- 保留蓝色作为唯一主品牌色
- 保留标题与正文双字体体系
- 保留大圆角和轻阴影，不要切回传统硬边框后台
- 保留低密度布局和充足留白
- 保留卡片化摘要展示，而不是一味表格化
- 保留轻量动画反馈，但控制总量

## 后续统一样式时建议收口的部分

目前最需要统一的不是方向，而是执行细节：

- 卡片圆角层级需要收口
- 阴影强度需要收口
- 状态色使用规则需要收口
- 按钮样式需要收口
- 表格、分页、标签、筛选器的风格需要收口
- 图标库最好逐步统一，避免长期混用

## 一句话总结

当前项目的设计风格，是一套偏现代、轻品牌化、卡片驱动、低密度的大圆角库存管理后台设计语言。
